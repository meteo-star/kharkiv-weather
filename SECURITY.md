# Безопасность и приватность

Этот документ описывает, как приложение обращается с данными пользователя. Если ты нашёл потенциальную уязвимость – напиши на email из коммитов автора.

## Принципы

### 1. Никакого бэкенда

Сайт – чистая статика, размещённая на GitHub Pages. Нет своего сервера, нет базы данных, нет логов в нашей зоне ответственности. Все вычисления происходят в браузере пользователя.

### 2. Никакой аналитики и трекеров

- Нет Google Analytics, Hotjar, Matomo и подобных метрик
- Нет сторонних рекламных сетей
- Нет cookie-баннеров, потому что нет cookie

### 3. Геолокация – только по явному действию

- Координаты не запрашиваются автоматически при загрузке
- Запрос только после нажатия кнопки «Моё местоположение»
- Координаты используются только для запроса прогноза, не передаются третьим лицам сверх необходимого
- Сохраняются только в `localStorage` пользователя (на его устройстве)

### 4. localStorage – только локально

В `localStorage` сохраняются:
- Выбранный город/координаты
- История точности источников (для self-rating)
- Пользовательские настройки

Эти данные **никогда** не покидают устройство пользователя.

### 5. HTTPS принудительно

GitHub Pages обслуживает сайт только по HTTPS. В `<head>` страницы установлен заголовок `Strict-Transport-Security` через `<meta>`.

### 6. Content Security Policy

В `<head>` установлен CSP-заголовок, ограничивающий источники скриптов, стилей, шрифтов и API. Никакой посторонний скрипт не сможет инжектиться в страницу.

### 7. Subresource Integrity (SRI)

Внешние ресурсы с CDN (Chart.js, шрифты) подключены с атрибутом `integrity` – браузер откажется выполнить файл, если его контрольная сумма не совпадает с ожидаемой.

### 8. Никаких API-ключей в коде

Все используемые API – без ключей и без аутентификации:
- Open-Meteo (forecast, archive, air quality, pollen)
- MET Norway (опционально, требует User-Agent)
- Blitzortung WebSocket

Если в будущем понадобится API с ключом – ключ не попадёт в публичный репозиторий, используется прокси через Cloudflare Worker.

### 9. Прозрачность внешних запросов

При работе сайта браузер обращается к следующим внешним сервисам (это нормальное для веба, но важно знать):

| Сервис | Что видит | Куда уходят данные |
|---|---|---|
| `api.open-meteo.com` | IP, координаты, User-Agent | Open-Meteo (Швейцария, GDPR) |
| `air-quality-api.open-meteo.com` | IP, координаты | Open-Meteo |
| `archive-api.open-meteo.com` | IP, координаты, диапазон дат | Open-Meteo |
| `geocoding-api.open-meteo.com` | IP, поисковый запрос (название города) | Open-Meteo |
| `nominatim.openstreetmap.org` | IP, координаты пользователя (при использовании геолокации) | OpenStreetMap Foundation (UK) |
| `fonts.googleapis.com` / `fonts.gstatic.com` | IP, User-Agent | Google (один раз кэшируется) |
| `cdn.jsdelivr.net` | IP, User-Agent | jsDelivr (Cloudflare) |
| `ws.blitzortung.org` (опционально) | IP | Blitzortung (Германия, open data) |

Никаких **персональных данных** (имя, email, история действий) этим сервисам не передаётся.

### 10. Web Push (когда появится)

- Подписка только по явному клику пользователя
- Отписаться можно одной кнопкой в настройках
- Без фарма аудитории и без «продажи» уведомлений

## Что НЕ хранится

- Имена, email, телефоны
- История поиска
- Идентификаторы устройства, fingerprint
- Cookie любого вида

## Зависимости и обновления

Все внешние библиотеки (Chart.js) подключены с фиксированной версией. Обновление – только осознанное, с пересчётом SRI-хэша.

## Контакт

Вопросы по безопасности – через Issues репозитория или напрямую к maintainer'у.
